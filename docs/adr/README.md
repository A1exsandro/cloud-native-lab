# Architecture Decision Records (ADR)

This directory contains the Architecture Decision Records (ADRs) for the Cloud Native Lab project.

An ADR documents a significant architectural decision, including its context, rationale and consequences.

The objective is to preserve the reasoning behind important technical choices, making the project easier to understand and maintain over time.

---

## ADR Lifecycle

Every ADR follows the same lifecycle:

1. Identify the problem
2. Evaluate alternatives
3. Make a decision
4. Document the rationale
5. Implement
6. Review when necessary

---

## ADR Status

Each ADR should include one of the following statuses:

- Proposed
- Accepted
- Deprecated
- Superseded

---

## Naming Convention

ADRs use sequential numbering.

Example:

0001-project-principles.md

0002-oracle-cloud.md

0003-debian-13.md

---

## Template

New ADRs should be created from `template.md`.

---

## Philosophy

Architectural decisions should never exist only in someone's memory.

Every important decision should be documented so future contributors understand not only **what** was chosen, but **why** it was chosen.
